
===== PAGE 1 =====
本实验从单机多线程走向多机多进程。需要实现两种  MPI 通信策略，并与一个朴素的全量广播基线作对比。
单机多线程时，所有线程共享同一份数据，通信由硬件的缓存一致性隐式完成。换成多台机器后，进程之间没有共享
内存，数据要显式地传过去。图计算在这里格外棘手：图一旦切开，节点的邻居就可能落在别的机器上。本次实验要
比较的，就是两种把这些边界数据传过来的方式。
实验在华为云鲲鹏  ECS 集群上完成。集群的购买与配置见附录  A ，建议先按附录  A 把  4 台机器和免密、 MPI 装好，再
回到第  1 节。
图有  N 个节点，每个节点有  d 维特征，邻接关系用  CSR （ Compressed Sparse Row ）存储。一层图卷积为
也就是：先把每个节点的邻居特征取平均（邻居聚合），再做一次线性变换，最后过  ReLU 。本实验最后一层不加激
活。
D^-1 A H 是稀疏矩阵乘稠密矩阵（ SpMM ），相当于把稀疏矩阵向量乘（ SpMV ）中的向量换成了一个  N × d 的矩
阵。每个非零元素带来的算术操作很少，所以性能主要受访存和负载均衡影响；放到多机环境后，还要再加上一项通
信开销。
本实验只做推理（前向传播），不做训练。权重由固定种子生成，所有进程得到相同的权重，因此权重不需要通信。
每个进程负责一段节点，保存它们的特征。计算第  l+1 层时，进程需要所有邻居在第  l 层的表示，而其中一部分邻
居属于别的进程。这些 " 本进程计算时需要、但不属于本进程 " 的节点叫  halo 节点。
第  l+1 层用的是邻居在第  l 层的表示，而这个表示每层都在变，所以  L 层网络要交换  L 次。
配套代码使用统一的本地编号空间：[0, localN) 是本进程拥有的节点，[localN, localN + haloN) 是  halo 
区。
设进程  p 的  halo 节点数为  h_p，第  l 层维度为  d_l。一次完整推理中，进程  p 接收的数据量约为
注意  h_p 由图的划分质量决定，而不是由进程数简单决定；多条边指向同一个远程节点时，该节点只需要传一次。所
以跨进程边数和  halo 节点数是两个不同的量，它们的增长也不成比例。

gnnSetup —— 建立通信计划，在划分之后、计时开始之前调用一次。难点在于每个进程只知道自己需要哪些远程节
点，却不知道别人需要自己的哪些节点，而发送方必须知道该发什么。
gnn_mpi_student_1 —— 用集合通信完成每层的  halo 交换。每个进程发给不同对端的数据量不同，属于不规整通
信。
gnn_mpi_student_2 —— 用点对点通信完成每层的  halo 交换，并让通信与计算重叠。只换接口而不做重叠，不算
完成第二种策略。
gnn_mpi_allgather —— 对照基线，每层把所有节点的表示收集到所有进程。正确性最容易保证，但每个进程都要
存下全图，内存占用不随进程数下降。
可用的接口：MPI_Alltoall、MPI_Alltoallv、MPI_Allgatherv、MPI_Isend / MPI_Irecv / MPI_Waitall。
注意  MPI 的  counts / displs 单位是元素个数。
不要调用  PETSc 、 Trilinos 等库的分布式  SpMM 接口代替自己的  MPI 实现。
比较并行实现时，图、权重、层数、隐层维度都要相同。不能通过少算节点、跳过某些层或修改参考结果来缩短时
间。
checkResult 把各进程的局部结果收集到  rank 0 ，与串行参考逐元素比较，并检查每个节点恰好被一个进程输出。
容差  atol = rtol = 1e-7。
需要覆盖的情况：单进程与多进程、 block 与  cyclic 、单层与多层、进程数不整除节点数、孤立点。

int main(int argc, char **argv) {
    MPI_Init(&argc, &argv);
    int rank, size;
    char name[256];
    int len;
